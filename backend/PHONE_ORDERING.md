# Phone Ordering Recording Path

Shopkeepers place calls with the device `tel:` dialer. e-Setu does not automatically record ordinary cellular calls. On this PWA there is no native Android `InCallService`; Android's `CallScreeningService` exposes call metadata, not media, and the `VOICE_CALL`, `VOICE_UPLINK`, and `VOICE_DOWNLINK` audio sources require `CAPTURE_AUDIO_OUTPUT`, a permission reserved for system components. A microphone-only capture would not reliably contain both sides, so it is intentionally not presented as call recording.

Free manual path: return to `कॉल`, open the correct recent supplier call, select `रिकॉर्डिंग जोड़ें`, and choose a WAV, MP3, or M4A call recording. The server validates the size and audio decoding, checks the SHA-256 digest, associates the file with that existing call and its supplier/customer data, and hands it to the existing STT -> extraction -> supplier review pipeline. Unknown customers remain unknown until explicitly identified. A recording or draft already attached to the call is never silently replaced.

Suppliers can choose a shopkeeper, launch a normal device `tel:` call, and attach its recording to that logged call. A supplier may also send a targeted 10-minute wait notice to a known shopkeeper. The expiry and supplier/call association are stored on the shopkeeper account, the notice uses the existing OneSignal subscription when available, the Calling screen shows a decreasing countdown, and the call-log API atomically rejects new shopkeeper app calls until the wait expires. A supplier-initiated call remains available during that window. This only blocks calls started through e-Setu; the web app cannot prevent someone from dialing manually outside it.

Audio is stored privately on the backend filesystem, streamed only through authenticated endpoints, limited to 64 MB by default, and removed after the configured retention period (30 days by default). Deployments with ephemeral disks must expect the recording to disappear at restart; this is not durable audio archive storage. After retention cleanup, file and digest references are cleared so an upload can be retried only when no transcript/review pilot already exists for that call.

A real Android implementation would require a separate native dialer app selected as the user's default phone app plus device/OEM and policy validation. It is not a capability this browser/PWA can add. The existing STT/review and protected confirmed-draft-to-Order bridge remain the sole order pipeline.
